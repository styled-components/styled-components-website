## Plugins moved to a dedicated subpath

```tsx
import { StyleSheetManager } from 'styled-components';
import { prefixPlugin, rtlPlugin } from 'styled-components/plugins';

<StyleSheetManager plugins={[prefixPlugin, rtlPlugin]}>
  <App />
</StyleSheetManager>
```

The `stylisPlugins` prop on `<StyleSheetManager>` is now `plugins`, and `enableVendorPrefixes` has been removed in favor of `prefixPlugin`. `stylisPluginRSC` has been removed completely because v7 routes server component styles through the style registry instead of emitting inline `<style>` tags. Tree-shaking removes plugins from any app that doesn't import them.

### `rtlPlugin`

Replaces `stylis-plugin-rtl` for users coming from v6:

- Swaps physical side properties (`padding-left` ↔ `padding-right`, `margin-left` ↔ `margin-right`, `border-left` ↔ `border-right`, etc.).
- Flips `left` / `right` keyword values on `float`, `clear`, `text-align`, and `caption-side`.
- Mirrors 4-value shorthand positions (`margin: 0 4px 0 8px;` becomes `margin: 0 8px 0 4px`).
- Logical properties like `margin-inline-start` pass through unchanged because they already resolve correctly per the document direction.

### Plugins and namespaces in server components

In server components, a `<StyleSheetManager>` applies only to the server components rendered inside it. A manager in a Next.js layout styles the layout's own markup, not its pages. To give every server component the same plugins or namespace, call `configureServerStyles` once at the top level of your root layout file:

```tsx
// app/layout.tsx
import { configureServerStyles } from 'styled-components';
import { rtlPlugin } from 'styled-components/plugins';

configureServerStyles({ namespace: '#app', plugins: [rtlPlugin] });

export default function RootLayout({ children }: { children: React.ReactNode }) {
  // ...
}
```

Both `namespace` and `plugins` are optional, and each call sets both (a later call without `namespace` clears it). The call is a plain statement, not a component, so it reaches every page, nested layout, and client-side navigation, including pages prerendered at build time. Make one call per app: a later call replaces an earlier one and applies to renders that start after it.

Do not put it in `instrumentation.ts`. Next.js does not run that file while prerendering pages at build time, so prerendered pages would miss the settings.

A `<StyleSheetManager>` in a server component starts from these settings; its own `plugins` or `namespace` prop replaces them, and `plugins={[]}` or `namespace=""` drops them for its subtree. `configureServerStyles` applies to server components only. Client components take their plugins and namespace from a `<StyleSheetManager>` that renders in both SSR and the browser. Do not add `plugins` or `namespace` to a registry `<StyleSheetManager>` that sits behind an `if (typeof window !== 'undefined') return <>{children}</>;` guard: either always render `<StyleSheetManager sheet={typeof window === 'undefined' ? styledComponentsStyleSheet.instance : undefined} plugins={[rtlPlugin]}>` or wrap the registry in a separate client `<StyleSheetManager>`, otherwise SSR and client hydration hash with different compilers and mismatch.

Placing a layout manager to style every page has been removed in favor of `configureServerStyles`.

### `prefixPlugin`

Adds vendor prefixes to the CSS you author, scoped to the browsers that support the JavaScript APIs React requires (Chrome 45, Firefox 36, Safari 9 / iOS 9, Edge 12). A construct is prefixed only where one of those browsers still needs it: `appearance`, `user-select`, `backdrop-filter`, `position: sticky`, `filter`, `clip-path`, the `mask*` family, `tab-size`, `writing-mode`, `hyphens`, `image-set()` in values, multi-column `column*`, `line-clamp`, `font-feature-settings`, `box-decoration-break`, `text-size-adjust`, `scroll-snap-type`, the inline logical `margin` and `padding` longhands, and the `::placeholder`, `:read-only`, and `:read-write` selectors. Prefixed declarations are emitted ahead of the standard one, so a browser that understands the standard form uses it.

```tsx
import { StyleSheetManager } from 'styled-components';
import { prefixPlugin } from 'styled-components/plugins';

<StyleSheetManager plugins={[prefixPlugin]}>
  <App />
</StyleSheetManager>
```

Opt in per subtree; a `<StyleSheetManager>` without it emits unprefixed CSS. Flexbox, transforms, transitions, animations, and gradients need no prefix at that floor and pass through unchanged, as do declarations you author already prefixed. For a different browser floor or prefix set, compose your own plugin after it; see [Authoring custom plugins](#authoring-custom-plugins).

### Authoring custom plugins

The v7 plugin contract is narrower than the stylis-style middleware shape used in v6. A plugin is a plain object with a `name`, plus either or both of `rw` (selector rewrite) and `decl` (declaration rewrite):

```ts
import type { SCPlugin } from 'styled-components/plugins';

const scopePlugin: SCPlugin = {
  name: 'scope',
  // `rw` runs on every fully-resolved selector after `&` substitution and
  // namespace prepending. Return a new selector string, or an array of
  // selectors to emit one rule per entry.
  rw: selector => `.app ${selector}`,
  // `decl` runs on every emitted `prop: value` pair (top-level decls, decl
  // bodies under at-rules, and decl bodies under nested rules). Return
  // `{ prop, value }` to rewrite the pair, an array of pairs to expand one
  // declaration into several, or `undefined` to leave it unchanged. Each
  // plugin in a chain composes left-to-right, and a later hook sees every
  // result an earlier plugin emitted.
  decl: (prop, value) => {
    if (prop === 'cursor' && value === 'pointer') {
      return { prop, value: 'default' };
    }
    return undefined;
  },
};
```

The `name` field is required and contributes to the compiler's cache hash, so different plugin sets across nested `<StyleSheetManager>` trees stay isolated. Plugins without a name throw a styled-components error, and development builds warn when two different plugins share a `name` under the same `namespace`.

Legacy stylis plugins (those exporting a single function) don't run in v7 because they don't expose `rw` or `decl`. Development builds warn once when a plugin cannot run: a middleware function, or an object with neither hook. Migrate them to the `SCPlugin` interface above; complex use cases that need a richer hook surface should open an issue.
