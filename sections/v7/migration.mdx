## Migrating from v6

Most v6 apps move to v7 by bumping the version, updating peers, and applying a few small changes. The list below is exhaustive; pick out the items that apply.

Install the current v7 prerelease with `npm install styled-components@test`.

### Update peers

- `react` and `react-dom` to `^19`.
- `react-native` to `^0.85` if you use it.
- `react-native-reanimated` to `^4` if you opt into the native animation adapter.
- `react-native-safe-area-context` to `^5` if you want `env(safe-area-inset-*)` to read automatically from `<SafeAreaProvider>` (or pass insets yourself with `SafeAreaInsetsProvider`).
- `react-native-web` to `^0.20` if you target web from `styled-components/native`.
- Drop `css-to-react-native` if it was in your `package.json` only for styled-components.

### Server component styles require the style registry (`stylisPluginRSC` removed)

Server component styles now go through your style registry (`ServerStyleSheet` + `StyleSheetManager`), the same registry client components use. Inline `<style>` tags in server component output have been removed, and `stylisPluginRSC` has been removed because no style tag sits between sibling elements anymore: `:first-child`, `:nth-child()`, sibling selectors, and SVG children match natively in server HTML.

Wrap `<html>` in the registry in your root layout so every server styled component (including a styled `<html>` or `<body>`) renders inside it:

```tsx
// app/layout.tsx
import StyledComponentsRegistry from './lib/registry';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <StyledComponentsRegistry>
      <html>
        <body>{children}</body>
      </html>
    </StyledComponentsRegistry>
  );
}
```

A server styled component rendered without the registry above it gets no styles in the server-rendered HTML (its styles apply after hydration and development warns once). `global-error.tsx` renders only in the browser, so its styles always apply after hydration.

- If you had a layout `<StyleSheetManager stylisPlugins={[stylisPluginRSC]}>`, delete it.
- If you pass `plugins` or `namespace` to `<StyleSheetManager>` for client components, render that manager in the browser as well (not behind `if (typeof window !== 'undefined') return <>{children}</>;`), or wrap the registry in a separate client `<StyleSheetManager>`, otherwise SSR and client hydration hash with different compilers.
- Supported hosts: Next.js with webpack or Turbopack (listing `styled-components` in `serverExternalPackages` is not supported) and Vite with `@vitejs/plugin-rsc` (with the registry in the SSR entry). Routes rendering styled-components on the server require the Node.js runtime; the edge runtime is not supported.

### `defaultProps` is no longer honored

React 19 removed `defaultProps` from function components, so styled components can no longer inherit them either. Use `.attrs()` for prop defaults and `<ThemeProvider>` for default themes.

```tsx
// Before (v6, no longer applies in v7)
const Button = styled.button``;
Button.defaultProps = { type: 'button' };

// After: object form always wins
const Button = styled.button.attrs({ type: 'button' })``;

// After: function form lets user props override
const Button = styled.button.attrs<{ type?: string }>(p => ({
  type: p.type ?? 'button',
}))``;
```

### `disableCSSOMInjection` and `SC_DISABLE_SPEEDY` removed; use `extractCSS()`

The browser build always uses the fast injection path. If you were toggling into a slower text-based mode to read the CSS as a string (for static-render pipelines, micro-frontend cloning, embedding into iframes or Shadow DOM), call the new `extractCSS()`:

```js
import { extractCSS } from 'styled-components';

// after rendering
const css = extractCSS();
```

The result is plain CSS, safe to inject into another document via `innerHTML`. The v7 SSR escaping rule applies: `</style>` substrings in interpolated values are rendered as the CSS hex escape `\3C/style` so they cannot terminate a host `<style>` tag.

### `enableVendorPrefixes` removed

The `enableVendorPrefixes` prop and the runtime vendor prefixer have been removed in favor of the opt-in [`prefixPlugin`](#prefixplugin) from `styled-components/plugins`, which prefixes the CSS that still needs it at React's browser support floor. Declarations you author already prefixed pass through untouched, and you can [compose your own plugin](#authoring-custom-plugins) for a different prefix set.

### Plugins moved to a subpath

The v6 `stylisPlugins` prop has been removed in favor of first-party plugins from `styled-components/plugins`, passed via the renamed `plugins` prop:

```diff
-import rtl from 'stylis-plugin-rtl';
+import { prefixPlugin, rtlPlugin } from 'styled-components/plugins';

-<StyleSheetManager stylisPlugins={[rtl]} enableVendorPrefixes>
+<StyleSheetManager plugins={[prefixPlugin, rtlPlugin]}>
```

In server components, a layout manager styles only the layout's own markup, not its pages. Call `configureServerStyles({ plugins, namespace })` at the top level of your root layout file instead (see [Plugins and namespaces in server components](#plugins-and-namespaces-in-server-components)).

`stylis-plugin-rtl` is replaced by the first-party `rtlPlugin`. Custom stylis plugins authored against the v6 middleware contract no longer load and must port to the new `SCPlugin` shape. See [Plugins moved to a dedicated subpath](#plugins-moved-to-a-dedicated-subpath) for details and authoring guidance.

### Nested `StyleSheetManager` inherits `namespace`

A nested `<StyleSheetManager>` without a `namespace` prop now inherits its parent's namespace in both client and server components. To render a subtree without the inherited namespace (for example, a portal mounted outside the container), pass `namespace=""`.

### Global styles precede component styles and emit once

Definition-order placement of `createGlobalStyle` relative to components has been removed in favor of globals-first placement: every global style sits before every component style (server globals before client globals, keyframes with the globals of the side that defined them), so a component wins a tie with a global whichever was defined first. Raise the global selector's specificity if it needs to beat a component.

Mounting the same `createGlobalStyle` component multiple times emits its CSS once in client and `ServerStyleSheet` rendering. If your app deliberately remounts the same global to re-apply styles, mount once per global rule set instead.

### No split blocks across template and interpolation

Splitting a CSS block, string, or parenthesis across a template literal and an interpolation (leaving `calc(`, a string, or `[` open in the template for an interpolated value to close) has been removed. Write matching delimiters in one place. A value that opens and closes its own delimiter later in the same declaration (such as ``width: ${'calc('}1px${')'};``) still works.

### `StyleSheet.prototype.reconstructWithOptions` removed

`StyleSheet.prototype.reconstructWithOptions` has been removed. Pass `target` or `nonce` to `<StyleSheetManager>` in the browser, or `nonce` to `new ServerStyleSheet({ nonce })` during SSR.

### Interpolations run on every render and `.attrs()` wins over `undefined`

Style interpolations and `.attrs()` callbacks run on every render (on web and native, and inside `createGlobalStyle` too), so calling a React hook or reading external state inside an interpolation never causes hook-order crashes or stale styles. Wrap frequently re-rendering components in `React.memo` if you want to skip re-renders when props are unchanged.

`.attrs()` always applies its value even when a caller explicitly passes `undefined` (for example `<Button type={undefined} />` still receives `type="button"` from `.attrs({ type: 'button' })`). To let an explicit `undefined` clear an `.attrs()` default, use the function form and check `'prop' in props`.

### React Native bumps and changes

The [CSS Compatibility matrix](/docs/compatibility) is the per-feature source of truth for what changed between v6 and v7 on web and native. The most common gotchas:

- The peer floor moves to RN ≥ 0.85.
- `border: none` now emits `border-style: none` (previously `solid`, which produced surprising hairlines).
- The optional reanimated adapter is opt-in at app entry: `import 'styled-components/native/reanimated'`. `react-native-reanimated@^4` becomes a peer dependency only in that case. The adapter is experimental and not heavily tested yet; the default `Animated`-based adapter runs without any setup.

[React Native gets modern CSS](#react-native-gets-modern-css) walks through the new surface (modern color spaces, gradients, filters, selectors, animations, `createTheme()`) and calls out the platform-level caveats (iOS SwiftUI filter opt-in, hover feature flag, conic-gradient gap, and the rest). The compatibility matrix has the per-feature breakdown.

### TypeScript

- `IInlineStyle` and `IInlineStyleConstructor` were renamed to `INativeStyle` and `INativeStyleConstructor`. The old names are exported as deprecated aliases.
- `Stringifier` is exported as a deprecated alias for the new `Compiler` interface (the shape differs, so consuming code that called the type as a function will need to migrate to `Compiler.compile` / `Compiler.emit`).
- `Flattener` and `NameGenerator` are gone (private helpers, never documented).
