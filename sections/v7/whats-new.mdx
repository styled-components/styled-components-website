## What's new in v7

> **v7 is in alpha.** This release is under active development, and the docs will receive **frequent updates over the next few weeks** as internals are refined.
>
> Install the prerelease from npm's `@test` dist-tag:
>
> ```bash
> npm install styled-components@test
> ```

v7 is an architectural reform for the web and the start of a new chapter for `styled-components/native`. We replaced stylis with an in-house CSS parser, rewrote the native runtime from the ground up, and set a clear direction for native: the same CSS should feel the same everywhere, whether you render on web, iOS, or Android.

  The [React Native CanIUse](/docs/compatibility) page shows how far v7 has moved that goal already, and where there is still platform work to do.
</CompatibilityPreviewCard>

The bottleneck now is funding. styled-components can help provide a universal React visual surface while strengthening React Native's styling ecosystem at the same time; recent [upstream React Native PRs](https://github.com/facebook/react-native/pulls?q=is%3Apr+author%3Aquantizor+) are already filling gaps around `textAlignVertical`, `textDecorationStyle`, `textDecorationColor`, and text decoration rendering. [Donations and sponsorship](https://opencollective.com/styled-components) make it possible to do that work outside of "passion time".

### Highlights

- **In-house CSS parser** replaces stylis as the runtime engine. No more `:is()` / `:where()` / `:has()` recursion bugs, no more silent breakage on modern at-rules (`@view-transition`, `@position-try`, `@page` margin boxes, `@font-feature-values`).
- **Registry-routed server component styles.** Server components no longer emit inline `<style>` tags; their styles route through your style registry alongside client components in tree order. `:first-child`, `:nth-child()`, sibling selectors, and SVG children work natively in RSC without a plugin, and styles survive `<Suspense>` reveals and route transitions.
- **Predictable cascade ordering.** Global styles from `createGlobalStyle` always precede component styles (server globals before client globals), and a component wrapping another on the same element (`styled(X)`, `as={X}`, or a forwarded `className`) always beats the component it wraps regardless of definition or load order.
- **View Transitions.** A component setting `view-transition-name` automatically receives its own class as `view-transition-class`, so `::view-transition-group(*${Card})` in `createGlobalStyle` targets it directly. `view-transition-class: ${Card}` and `container-name: ${Card}` also emit the component's class.
- **Modern CSS on React Native.** `@media` and `@container` queries, viewport and container-query units, font-relative units, `env(safe-area-inset-*)` (via `react-native-safe-area-context` or `SafeAreaInsetsProvider`), modern color spaces, relative-color syntax, the full Math L4 family, logical shorthands, gradients, filters, and `corner-shape` (`round`, `square`, `squircle`) all work in `styled.View\`...\``. See [React Native gets modern CSS](#react-native-gets-modern-css) for the full surface and the [compatibility matrix](/docs/compatibility) for per-feature status.
- **Selectors and combinators on React Native.** Attribute selectors with every operator, `:not(<simple>)`, `:has(<simple>)`, tree-structural pseudos, the four combinators between styled-component references, and the `:hover` / `:focus` / `:pressed` / `:disabled` / `:enabled` / `:read-only` / `:read-write` pseudo-states.
- **Native animations** by default. `transition`, `@keyframes`, and `@starting-style` run on React Native through the built-in `Animated`-based adapter, with no setup or peer dependency. An optional reanimated adapter is available behind one import (experimental; not heavily tested yet).
- **`createTheme()` on native**, with the same contract as web. `<ThemeProvider>` deep-merges nested themes so an inner override that touches one leaf keeps the siblings it inherited.
- **Dedicated `react-native-web` build.** `styled-components/native` ships a smaller bundle for rn-web targets that defers to the browser for `light-dark()` + `prefers-color-scheme` repaints, distinct `dvh` / `svh` / `lvh` / `vi` / `vb` resolution, wide-gamut `oklch` / `oklab` / `lch` / `lab` / `color-mix()`, paint-time `calc()` / `clamp()` / `min()` / `max()` against the real containing block, and `onAnimationEnd` / `onTransitionEnd` callbacks. Webpack, Vite, and Metro web targets detect it automatically; other bundlers can import `styled-components/native/web-bridge` directly.
- **Plugins subpath.** `import { prefixPlugin, rtlPlugin } from 'styled-components/plugins'`. First-party RTL replaces `stylis-plugin-rtl`, and opt-in `prefixPlugin` restores vendor prefixing at React's browser support floor; custom plugins move to a narrower `SCPlugin` interface. In server components, `configureServerStyles({ plugins, namespace })` in the root layout file sets the process-wide defaults for every page. See [Plugins moved to a dedicated subpath](#plugins-moved-to-a-dedicated-subpath).
- **`extractCSS()`** reads the current stylesheet as plain text. Replaces the legacy `disableCSSOMInjection` toggle.
- **Global styles emit once.** Mounting the same `createGlobalStyle` component multiple times emits its CSS once in client and `ServerStyleSheet` rendering.
- **Remapping CSS into native props** via the function form of `.attrs((props, ast) => ...)`. Most useful for React Native libraries that style via props (e.g. `react-native-svg`'s `<Path fill="..." />`, `Image`'s `tintColor`, icon libraries). [Details →](/docs/basics#bridging-styles-into-props)
- **TypeScript improvements.** Polymorphic `as` targets drive editor attribute completion (`<Component as="video" ...>` completes `loop`, `muted`, `controls`, `poster`), and `StyledComponent<Target, Props>` is exported on web and native for explicit export annotations and `isolatedDeclarations`.
- **Smaller browser bundle and faster SSR at scale.**

### Peer dependency floors

- `react` and `react-dom` ≥ 19.0.0
- `react-native` ≥ 0.85.0 (optional peer)
- `react-native-reanimated` ≥ 4.0.0 (optional peer, only required if you opt into the reanimated animation adapter)
- `react-native-safe-area-context` ≥ 5.0.0 (optional peer, for automatic `env(safe-area-inset-*)` resolution under `<SafeAreaProvider>`)
- `react-native-web` ≥ 0.20.0 (optional peer)

Older React or React Native projects should stay on v6.
