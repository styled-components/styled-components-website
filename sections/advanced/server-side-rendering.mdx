## Server Side Rendering | v2+

styled-components supports concurrent server side rendering, with stylesheet rehydration.
The basic idea is that every time you render your app on the server, you can create
a `ServerStyleSheet` and add a provider to your React tree, that accepts styles
via a context API.

This doesn't interfere with global styles, such as `keyframes` or `createGlobalStyle` and
allows you to use styled-components with React DOM's various SSR APIs.

### React Server Components | v6.3.0+

styled-components natively supports React Server Components (RSC) without needing `'use client'` on styled component modules.

Key behaviors in RSC:

- No `'use client'` directive required on styled components
- `ThemeProvider` becomes a pass-through component (no context in RSC); use [`createTheme()`](/docs/api#createtheme) instead
- `StyleSheetManager` works in RSC as of v6.4 (`stylisPlugins` / `plugins`, `namespace`, and `shouldForwardProp` apply)
- In v6.3–v6.7, server components emit inline `<style>` tags automatically. In **v7**, server component styles route through your style registry (`ServerStyleSheet` + `StyleSheetManager`) with no inline `<style>` tags: wrap `<html>` in the registry in your root layout, `:first-child` / `:nth-child()` / sibling selectors work natively without a plugin, and styles survive `<Suspense>` reveals and route transitions.
- Server-side rendering requires the Node.js runtime (edge runtime is not supported). In Next.js, do not list `styled-components` in `serverExternalPackages`.

Best practices for RSC:

| Do | Don't |
|---|---|
| Use [`createTheme()`](/docs/api#createtheme) for CSS variable theming | Rely on `ThemeProvider` / `p.theme` (no context in RSC) |
| Use data attributes for discrete variants (`&[data-size='lg']`) | Generate many classes via prop interpolations for a finite set of states |
| Use CSS custom properties via inline `style` for dynamic per-instance values | Use `@import` in `createGlobalStyle` (silently fails in production) |
| Wrap `<html>` in your style registry in v7 (or use `:first-of-type` / `stylisPluginRSC` in v6) | Render server styled components outside the registry in v7 |

#### Child-index selector caveat | v6 only

In v6.3–v6.7, RSC emits inline `<style>` tags as siblings of your styled elements. These tags are real DOM children, so `:first-child`, `:last-child`, and `:nth-child()` count them, shifting indices and breaking your styles. Use `:first-of-type` / `:nth-of-type()` instead, which filter by element type and are immune to this issue.

If you need `:nth-child()` specifically on v6, use the built-in [`stylisPluginRSC`](/docs/api#stylesheetmanager) plugin (v6.4+) which rewrites these selectors to exclude styled-components style tags. In v6.7+, call `configureServerStyles` at the top level of your root layout so it reaches every page (a layout `<StyleSheetManager>` styles only the layout's own markup):

```tsx
// app/layout.tsx (v6.7+)
import { configureServerStyles, stylisPluginRSC } from 'styled-components';

configureServerStyles({ stylisPlugins: [stylisPluginRSC] });
```

On v6.4–v6.6, wrap your layout in `<StyleSheetManager stylisPlugins={[stylisPluginRSC]}>`.

This uses CSS Selectors Level 4 `of S` syntax ([browser support](https://caniuse.com/css-nth-child-of-s): Chrome 111+, Firefox 113+, Safari 9+). In unsupported browsers, the entire CSS rule is dropped, so only opt in if your audience supports it.

In **v7**, inline `<style>` tags in server component output are removed in favor of the style registry, and `stylisPluginRSC` has been removed: `:first-child`, `:nth-child()`, sibling selectors, and SVG children work natively with no plugin and no browser floor. For other server-component plugins or namespaces in v7 (such as `rtlPlugin` or `namespace: '#app'`), call `configureServerStyles({ plugins, namespace })` at the top level of your root layout file; see [Plugins and namespaces in server components](/docs/v7#plugins-and-namespaces-in-server-components).

#### Theming with CSS custom properties

Since `ThemeProvider` has no effect in RSC (no React context), use CSS custom properties for theming instead. The recommended approach is [`createTheme()`](/docs/api#createtheme):

```tsx
import styled, { createTheme } from 'styled-components';

const theme = createTheme({
  colors: { primary: '#0070f3' },
});

// theme.colors.primary → "var(--sc-colors-primary, #0070f3)"
const Button = styled.button`
  background: ${theme.colors.primary};
`;
```

Or set variables manually on a parent element. They cascade to all DOM children:

```tsx
const Container = styled.div``;
const Button = styled.button`
  background: var(--color-primary, blue);
`;

<Container style={{ '--color-primary': 'orchid' }}>
  <Button>Inherits orchid background</Button>
</Container>
```

### Tooling setup

To ensure deterministic component IDs for server/client consistency, use our [Babel plugin](/docs/tooling#babel-plugin) or [SWC plugin](/docs/tooling#swc-plugin). Both provide equivalent functionality including SSR support, minification, and better debugging.

> If you use React Server Components (v6.3+), the plugins are optional for SSR but still provide minification and more legible class names in DevTools.

For Next.js users, the SWC plugin is built-in; just add `styledComponents: true` to your `next.config.js` compiler options.

### Example

The basic API goes as follows:

```tsx
import { renderToString } from 'react-dom/server';
import { ServerStyleSheet } from 'styled-components';

const sheet = new ServerStyleSheet();
try {
  const html = renderToString(sheet.collectStyles(<YourApp />));
  const styleTags = sheet.getStyleTags(); // or sheet.getStyleElement();
} catch (error) {
  // handle error
  console.error(error);
} finally {
  sheet.seal();
}
```

The `collectStyles` method wraps your element in a provider. Optionally you can use
the `StyleSheetManager` provider directly, instead of this method. Just make sure not to
use it on the client-side.

```tsx
import { renderToString } from 'react-dom/server';
import { ServerStyleSheet, StyleSheetManager } from 'styled-components';

const sheet = new ServerStyleSheet();
try {
  const html = renderToString(
    <StyleSheetManager sheet={sheet.instance}>
      <YourApp />
    </StyleSheetManager>
  );
  const styleTags = sheet.getStyleTags(); // or sheet.getStyleElement();
} catch (error) {
  // handle error
  console.error(error);
} finally {
  sheet.seal();
}
```

The `sheet.getStyleTags()` returns a string of multiple `<style>` tags.
You need to take this into account when adding the CSS string to your HTML output.

Alternatively the `ServerStyleSheet` instance also has a `getStyleElement()` method
that returns an array of React elements.

Render those elements without adding React's `precedence` or `href` props.
React-managed precedence tags lose the styled-components attributes required
for client adoption, so each server rule would otherwise be injected again
during hydration.

If rendering fails for any reason it's a good idea to use `try...catch...finally` to ensure that the `sheet` object will always be available for garbage collection. Make sure `sheet.seal()` is only called after `sheet.getStyleTags()` or `sheet.getStyleElement()` have been called otherwise a different error will be thrown.

> `sheet.getStyleTags()` and `sheet.getStyleElement()` can only be called after your element is rendered. As a result, components from `sheet.getStyleElement()` cannot be combined with `<YourApp />` into a larger component.

### Next.js

#### App Router (recommended)

In **v7**, add a style registry (`ServerStyleSheet` + `useServerInsertedHTML`) wrapping `<html>` in your root layout. It collects styles from both Server Components and Client Components in tree order, so no inline `<style>` tags are emitted and `:first-child` / `:nth-child()` work natively without a plugin. If you pass `plugins` or `namespace` for client components on `<StyleSheetManager>`, render that manager in the browser as well (not behind `if (typeof window !== 'undefined')`), or wrap the registry in a separate client `<StyleSheetManager>`.

In **v6.3–v6.7**, styled components in Server Components emit inline `<style>` tags without requiring a registry; a registry is still needed to collect styles from Client Components during SSR. If you use `:first-child` or `:nth-child()` selectors on v6, add `stylisPluginRSC` (via `configureServerStyles` in v6.7+, or `StyleSheetManager` in v6.4–v6.6; see [child-index selector caveat](#child-index-selector-caveat) above). See the [React Server Components](#react-server-components) section above for best practices.

With styled-components v6.0–6.2, you need to put a styled-components registry in one of your layout files, as [described in Next.js docs](https://nextjs.org/docs/app/building-your-application/styling/css-in-js#styled-components). The `'use client'` directive is required, so styled-components will appear in your client bundle.

#### Pages Router

Add `styledComponents: true` to the compiler options in `next.config.js`, then modify `_document` with `getInitialProps` to support SSR. See the [Next.js styled-components example](https://github.com/vercel/next.js/tree/canary/examples/with-styled-components) for reference.

If you're using Babel instead of SWC, refer to the [Babel-based example](https://github.com/vercel/next.js/tree/canary/examples/with-styled-components-babel).

### Streaming Rendering

styled-components offers streaming APIs for use with React's server rendering methods.

#### `renderToPipeableStream` (React 18+) | v6.2.0+

The recommended approach for streaming SSR uses React 18's `renderToPipeableStream`:

_On the server:_

```tsx
import { renderToPipeableStream } from 'react-dom/server';
import { ServerStyleSheet } from 'styled-components';

const sheet = new ServerStyleSheet();

const { pipe } = renderToPipeableStream(
  sheet.collectStyles(<YourApp />),
  {
    onShellReady() {
      // Set headers and pipe
      res.setHeader('content-type', 'text/html');
      pipe(res);
    },
    onAllReady() {
      sheet.seal();
    },
  }
);
```

_On the client:_

```tsx
import { hydrateRoot } from 'react-dom/client';

hydrateRoot(document.getElementById('root'), <YourApp />);
```

#### `renderToNodeStream` (legacy)

> `renderToNodeStream` is deprecated in React 18. Use `renderToPipeableStream` instead.

For legacy codebases still using `renderToNodeStream`, styled-components wraps the readable stream to interleave style blocks as HTML chunks are emitted:

```tsx
import { renderToNodeStream } from 'react-dom/server';
import styled, { ServerStyleSheet } from 'styled-components';

const sheet = new ServerStyleSheet();
const jsx = sheet.collectStyles(<Heading>Hello SSR!</Heading>);
const stream = sheet.interleaveWithNodeStream(renderToNodeStream(jsx));

stream.pipe(res, { end: false });
stream.on('end', () => res.end('</body></html>'));
```

After client-side rehydration is complete, styled-components will take over as usual and inject any further dynamic styles after the relocated streaming ones.
