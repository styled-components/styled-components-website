## Referring to other components

> This is a web-specific API. It is not available in React Native.

There are many ways to apply contextual overrides to a component's styling. That being said,
it rarely is easy without rigging up a well-known targeting CSS selector paradigm
and then making them accessible for use in interpolations.

styled-components solves this use case cleanly via the "component selector" pattern. Whenever
a component is created or wrapped by the `styled()` factory function, it is also assigned a
stable CSS class for use in targeting. This allows for extremely powerful composition patterns
without having to fuss around with naming and avoiding selector collisions.

A practical example: here, our Icon component defines its response to the parent Link being hovered:

```react
const Link = styled.a`
  display: flex;
  align-items: center;
  padding: 5px 10px;
  background: papayawhip;
  color: #BF4F74;
`;

const Icon = styled.svg`
  flex: none;
  transition: fill 0.25s;
  width: 48px;
  height: 48px;

  ${Link}:hover & {
    fill: rebeccapurple;
  }
`;

const Label = styled.span`
  display: flex;
  align-items: center;
  line-height: 1.2;

  &::before {
    content: '◀';
    margin: 0 10px;
  }
`;

render(
  <Link href="#">
    <Icon viewBox="0 0 20 20">
      <path d="M10 15h8c1 0 2-1 2-2V3c0-1-1-2-2-2H2C1 1 0 2 0 3v10c0 1 1 2 2 2h4v4l4-4zM5 7h2v2H5V7zm4 0h2v2H9V7zm4 0h2v2h-2V7z"/>
    </Icon>
    <Label>Hovering my parent changes my style!</Label>
  </Link>
);
```

We could have nested the color-changing rule within our Link component, but then we'd have to
consider both sets of rules to understand why Icon behaves as it does.

### Caveat

This behavior is only supported within the context of _Styled_ Components:
interpolating `A` in the following example will trigger a development warning because component
`A` is not a Styled Component.

```tsx
const A = () => <div />;

const B = styled.div`
  ${A} {
  }
`
```

In development, a `console.error` warning is emitted because `A` is a plain function component
being used as an interpolation; styled-components calls it as a function and gets an unexpected
result. The component still mounts, but the selector won't work as intended.

However, wrapping `A` in a `styled()` factory makes it eligible for interpolation -- just
make sure the wrapped component passes along `className`.

```tsx
const A = ({ className }) => <div className={className} />;

const StyledA = styled(A)``

const B = styled.div`
  ${StyledA} {
  }
`
```

### View Transitions and Container Names | v7+

In v7, a component that sets `view-transition-name` automatically receives its own class as `view-transition-class`, so a rule in `createGlobalStyle` can target the component inside a view transition pseudo-element:

```tsx
const Card = styled.li`
  view-transition-name: match-element;
`;

const Transitions = createGlobalStyle`
  ::view-transition-group(*${Card}) {
    animation-duration: 400ms;
  }
`;
```

`view-transition-class: ${Card}` and `container-name: ${Card}` also emit the component's class name so a component can be listed beside other names. Any `view-transition-class` you write yourself is kept as written.

### Referencing a `'use client'` component from server styles | v7+

A styled component defined in a `'use client'` module has no class a Server Component can read. When a Server Component's styles interpolate one (`${ClientCard}:hover &`, `@container ${ClientCard} (...)`), the selector, at-rule, or declaration holding it is left out of the server's CSS (with a development warning) while all other rules still apply. To target a component from server styles, define it in a module without `'use client'` and enable the build plugin (such as Next.js `compiler: { styledComponents: true }`) so the server and client graphs share one component id.
